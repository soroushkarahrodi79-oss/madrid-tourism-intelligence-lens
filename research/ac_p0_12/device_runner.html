How each number is produced (honesty notes)
  • interaction-to-paint — a double-rAF proxy (two frames), frame-quantised; it floors near one frame on a fast path and is not a true paint timestamp.
  • script work — the synchronous wall time of the production interaction call (moveLensToLatLng / slider oninput → refresh()). Captured for automated runs only.
  • pan frame time — the distribution of requestAnimationFrame deltas during the pan; the first (warm) frame is dropped.
  • freshness — after the gesture settles, the whole displayed membership set (code + “contains the Lens centre” bit + language, read from #planningMembership’s signature) must equal the canonical ambitosIntersecting set right now.
  • device-grade — a non-software GPU, a human label, an actual gesture, ≥ the sample target, and no conflict with the declared class.
Thresholds (from research/runtime_spike/device_harness/thresholds.json): interaction-to-paint p95 ≤ 100 ms good / ≤ 150 ms acceptable; pan frame p95 ≤ 16.7 ms good / ≤ 33.3 ms acceptable.
