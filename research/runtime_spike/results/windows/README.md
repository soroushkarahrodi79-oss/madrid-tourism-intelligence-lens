### What the run does and does not show

- **Interaction-to-paint** stays under the 150 ms acceptable line for *both* engines
  in every completed scenario (Leaflet 34–59 ms, MapLibre 39–98 ms). On this device,
  the Lens-drag analytical recompute is not the bottleneck.
- **Pan smoothness is where the engines diverge.** On this Intel UHD 620, Leaflet's
  `pan_frame_ms.p95` exceeds the 33.3 ms (30 fps) floor in **every** completed
  scenario — from the smallest 765-polygon case (469 ms) upward — while MapLibre
  stays at or near the floor (18–46 ms) across the entire completed matrix, including
  10 000 polygons and 50 000 points.
- Leaflet additionally **failed to complete** the 10 000-polygon case at all.

These are **directionally consistent** with the MapLibre migration thesis, but this
is a **single partial run on one integrated GPU**. `pan_frame_ms` is a
`requestAnimationFrame`-delta proxy (see `rum.js`), single-sample per count. No
conclusion is validated until a **complete** (`complete=true`, `comparable=true`)
device run exists — and, per `thresholds.json`, the ceiling must also be measured on
an **iPad-class device**, which Playwright cannot drive (see `../../device_harness/IPAD.md`
and the one-page iPad controller `../../device_harness/ipad_controller.html`).

## Recommended follow-up (bounded — do NOT rerun the whole suite)

The 37 completed scenarios are valid physical observations and should be kept. The
only missing cell is Leaflet `polygon/10000`. A scientifically sufficient follow-up
is a **single targeted re-measurement of that one pair**, not the full 38-scenario
matrix:

```
node research/runtime_spike/device_harness/run_device.mjs --suite=smoke \
     --channel=chrome --headed --label="Mi ordenador Windows fisico Chrome"
```

If the Leaflet 10 000-polygon case must be confirmed specifically, raise the harness
readiness timeout for that one run and expect it to either complete slowly or time
out again — a repeated timeout is itself the finding (Leaflet cannot render 10 000
polygons interactively on this GPU). Either way, treat the result as a **second
partial observation**; a Windows DEVICE_VALIDATION still requires one run where all
38 scenarios complete and every pair is comparable.
