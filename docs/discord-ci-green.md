# Discord CI green

`Discord CI green` runs from `main` after a completed `Test` workflow on a pull request. It never checks out the PR or downloads its artifacts. It verifies that the PR is still open against `main`, that its current head SHA matches the tested run (or its synthetic merge commit), that Test is successful, and that the current outcome of every one of the 14 expected jobs is successful. It also requires the PR head to have exactly those 14 successful check runs and no additional commit status contexts. A changed matrix or check set suppresses the message until this criterion is reviewed.

The job places a hidden PR comment keyed by PR number and head SHA before posting to Discord. GitHub Actions concurrency serializes runs for the tested SHA. Any existing marker, including one left by a failed or uncertain Discord request, suppresses later sends for that PR/SHA. If Discord fails, Test and merging are unaffected. There is no automatic retry: inspect the notifier log, remove that specific hidden comment, and rerun Test if a retry is appropriate. An accepted Discord request followed by a lost response is intentionally treated as uncertain, so the marker prevents a duplicate. If the marker cannot be created, no Discord request is made.

The workflow becomes eligible to run only after this file is on the default branch. A draft PR can validate the code, but it cannot demonstrate a message sent by `workflow_run` until the workflow is merged and a subsequent PR Test completes. Do not call the integration operational until a CI-originated message is observed in `#lens-ci`.
