## Local checkout vs deployed site

These are deliberately different evidence states, and the UI labels which one it
is showing:

| | A repository checkout | GitHub Pages |
|---|---|---|
| POI layers | `snapshot_poi.json` — 12 curated records, badged **SNAPSHOT SAMPLE** | `runtime_poi.json` — the deployment snapshot, badged **DEPLOYMENT SNAPSHOT** |
| Pedestrian counters | the committed `available: false` stub — the layer toggle is disabled | the built snapshot, when the source was reachable |
| Manifest | absent until you build | published at `<site>/data/deployment_manifest.json` |

A checkout intentionally carries no deployment snapshot: if it did, a developer
would be reading stale published evidence while believing it was current. To see
the deployed state locally, run the builders and then the validator:

```bash
node scripts/build_runtime_poi.mjs && python3 scripts/fill_stays_from_esmadrid.py && python3 scripts/build_pedestrian_activity.py && node scripts/validate_deployment.mjs
```

That needs network access. Afterwards, restore the committed pedestrian stub
with `git checkout -- data/pedestrian_activity.json`; `runtime_poi.json` and
`deployment_manifest.json` are git-ignored. The tests in
`tests/deployment_local_state.test.mjs` assert this split, so it cannot drift
silently.

Do not hand-edit `hati_assets.json` or `hati_provenance.json` — regenerate
them with `scripts/extract_hati_evidence.py` against a fresh HATI-Madrid
checkout if the upstream evidence changes.

Likewise, do not hand-edit `geography/madrid_admin.geojson` or its
`.meta.json` — regenerate them with `scripts/build_madrid_geography.py`
(needs network access and `shapely`, a builder-only dependency). The builder is
deterministic: an unchanged upstream produces a byte-identical `.geojson`, so a
diff there means the official boundaries or codes actually changed.

The same applies to `population/madrid_population.json` and its `.meta.json` —
regenerate them with `scripts/build_madrid_population.py` (needs network access;
standard library only, no `shapely`). Pass `--period YYYY` to pin a historical
1-January reference date; the default is the latest year whose barrio coverage
matches the canonical geography. The data artifact carries no build timestamp, so
an unchanged period produces byte-identical content; the retrieval time lives only
in the `.meta.json`.

`snapshot_poi.json` intentionally has no `bike` (BiciMAD) entries. An earlier
draft included hand-placed, approximate station coordinates; they were
removed because they could not be verified against the official EMT Madrid
dataset, and this project does not invent or approximate analytical
geospatial points. If BiciMAD's live source is unreachable, the app reports
that layer as unavailable instead. Every entry that does remain is a
**sample**, not a complete inventory — see `snapshot_provenance.json`'s
`completeness_notice`.
